# 本地建筑工作流候选

这条流程适用于两层、矩形、共用走廊和直跑楼梯的小型概念方案。原生 Rhino 曲线、Brep 和 Block 是交付模型；任务书中的面积目标和交通关系用于生成候选和验收。

| 步骤 | 行为 | 验收 |
|---|---|---|
| 1. 确定条件 | 在空白文档中给外框、层高、房间数量及面积范围、所需共墙关系和楼梯条件。先确认单位和尺度；未知值由用户确认。 | 未知关键条件不作为已经确认的输入。 |
| 2. 预览候选 | 本地求解器按楼梯核心和走廊约束，寻找一组房间顺序与尺寸。候选先经过源平面检查。 | 不向 Rhino 写对象；不可行时返回冲突和诊断。 |
| 3. 确认并建模 | 核对拟用的任务书和候选后确认。Miki-Rhino 用候选 ID 调用 Warehouse 的本地内核生成精确几何，保存任务书。 | 专门确认，即使启用了自动执行；候选不能用于另一个文档或覆盖现有模型。 |
| 4. 检查与修正 | 核对面积范围、越界、重叠、房间压墙及经门到楼梯的路径。求解生成的方案还要符合已确认的外框、层高、走廊、楼梯、房间清单和所需共墙关系。模型只收到有限条带 ID 的诊断。 | 用已确认任务书和当前 Rhino 实体复查；通用读回不能代替通过凭据。修改后复检；如果需求本身变了，先确认修订版任务书。 |
| 5. 保存、继续、交付 | 保存原生 3DM，重开恢复任务书和计划说明。需要 IFC 时从当前同步的模型导出，读回实体验证。 | 重开不会恢复旧的验收通过状态。重新检查时使用当前几何。 |

布局思路参考 [MANSION，CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Che_MANSION_Multi-floor_lANguage-to-3D_Scene_generatIOn_for_loNg-horizon_tasks_CVPR_2026_paper.html) 的跨层核心与几何约束，以及 [G2PLAN](https://doi.org/10.1111/CGF.14451) 的邻接与尺寸分工。当前实现用小范围枚举和动态规划，不需要论文的仿真器、资产或模型权重。通达性参考 [Hamieh 等，Automation in Construction](https://www.sciencedirect.com/science/article/pii/S0926580519308283)，按门和楼梯生成通达图。几何复用 RhinoCommon 与既有 Warehouse，不因分析离散成网格而改变原生交付几何。

完整离线运行时可使用候选求解与平面验收。公开轻量预览没有该运行时时，仍可用原生工具建模、修改和读回，界面明确显示缺少平面检查组件。此候选没有自动从扫描图识别空间，没有多种楼梯、曲墙或复杂立面的求解器。平面检查不是消防疏散、无障碍、结构或施工图审查。模型供应商的真实 token 和 Reer 同题成绩另测。

通达图排除概念上无法穿过的门洞：估计门框内侧可通宽度至少 0.60 m、高度至少 1.80 m。楼梯还检查梯段实体与墙体的冲突。以上用于拦截明显不合理的输入；不用于核定无障碍或疏散宽度，也没有计算门扇开启、真实行走距离或楼梯净高。
